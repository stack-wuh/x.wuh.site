归档已完成的变更。增量 specs 合并到 `openspec/specs/`，变更目录移至 `openspec/changes/archive/`。

**输入**: 可选指定变更名称（如 `/归档 2026-05-01-add-auth`）。如果省略，从对话上下文推断或列出可选变更。

**步骤**

1. **如果没有提供变更名称，提示选择**
   运行 `openspec list --json` 获取活跃变更列表，用 **AskUserQuestion** 让用户选择。
   只展示活跃变更（未归档的）。**不要自动选择**，始终让用户确认。

2. **检查制品完成状态**
   ```bash
   openspec status --change "<name>" --json
   ```
   - 如果有未完成的 artifacts: 警告用户并向用户确认是否仍然归档
   - 如果全部完成: 直接继续

3. **执行归档**
   ```bash
   openspec archive "<name>"
   ```
   这会:
   - 将 delta specs 合并到 `openspec/specs/`
   - 将变更目录移到 `openspec/changes/archive/YYYY-MM-DD-<name>/`

4. **验证**
   确认:
   - `openspec/changes/archive/YYYY-MM-DD-<name>/` 存在
   - `openspec/specs/` 中有更新后的 specs
   - `openspec/changes/<name>` 已不存在

**输出示例**

```
## 变更已归档

**变更:** 2026-05-01-standardize-api
**归档位置:** openspec/changes/archive/2026-05-01-standardize-api-and-migrate-frontend/

### 合并的 Specs
- content-api/spec.md → 分页格式 / 404 处理 / 查询参数校验
- repos-api/spec.md → GitHub 仓库接口
- error-handling/spec.md → 全局异常过滤器

完整历史记录已保存到 archive。
```

**注意事项**
- 归档前确认所有任务已完成
- 提醒用户: 归档是唯一修改 `openspec/specs/` 的时机
- 如果有未完成任务但用户坚持归档，记录未完成项
- 所有输出使用中文
- 归档不可逆，确认后再执行
