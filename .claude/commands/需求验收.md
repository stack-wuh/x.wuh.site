需求验收模式。在归档前验证变更是否完全符合 proposal/specs/tasks 中定义的要求。

**输入**: 可选指定变更名称。如果省略，从上下文推断或列出可选变更。

---

## 验收流程

### 1. 读取制品
读取变更目录下的所有制品:
- `proposal.md` → 确认变更范围
- `design.md` → 确认技术方案
- `tasks.md` → 确认任务完成状态
- `specs/` → 确认需求实现情况

### 2. 逐项验证

**tasks.md 验证:**
- [ ] 所有 checkbox 是否标记为 `[x]`？
- [ ] 是否有未完成的遗留任务？

**specs 需求验证:**
按 spec 中的每个 Requirement 检查:
- GIVEN/WHEN/THEN 场景是否被代码覆盖？
- 接口路径和响应格式是否匹配？

**代码质量检查:**
- 新增文件是否都在合适的位置？
- 是否有遗漏的模块注册（app.module）？
- 类型定义是否完整？

### 3. 生成验收报告

```
## 验收报告: <变更名称>

### 任务完成度
- [x] Task 1: xxx
- [x] Task 2: xxx
...
完成度: 6/6 ✓

### 需求覆盖
- content-api: ✓ 分页格式 / ✓ 404处理 / ✓ 查询校验
- repos-api: ✓ GitHub接口 / ✓ 缓存策略 / ✓ 容错降级

### 代码检查
- 类型检查: ✓ 通过
- 模块注册: ✓ 已注册
- 文件位置: ✓ 合理

### 验收结论
✓ 通过 — 可以执行 `/归档` 归档此变更
```

### 4. 验收不通过时
列出未通过项和修复建议，等用户修复后重新验收。

## 验收通过后
建议执行 `/归档 <变更名称>` 完成归档。

## 注意事项
- 验收是归档前的最后一道关卡
- 所有输出使用中文
- 不通过的项目给出具体修复建议
