创建新需求，一步生成所有规划制品。

生成制品清单:
- proposal.md (为什么做 / 做什么)
- design.md (技术方案)
- tasks.md (实施步骤清单)
- specs/ (增量需求规格)

执行完成后用 `/开始执行` 开始写代码。

---

**输入**: `/新需求` 后面是需求名称或一句话描述。

**步骤**

1. **如果没有提供输入内容，主动询问**
   用 AskUserQuestion 工具（开放式，无预设选项）询问:
   > "你想做什么需求？描述一下要构建或修复的内容。"
   从描述中提取变更名称（YYYY-MM-DD-{kebab-case} 格式，如 `2026-05-01-add-comment-api`）。

2. **创建变更目录**
   ```bash
   openspec new change "<name>"
   ```

3. **获取制品生成顺序**
   ```bash
   openspec status --change "<name>" --json
   ```

4. **按依赖顺序逐一创建制品**
   按依赖关系循环创建 artifacts:
   a. 对每个就绪的 artifact:
      - 获取指令: `openspec instructions <artifact-id> --change "<name>" --json`
      - 读取依赖制品文件获取上下文
      - 使用 `template` 作为结构创建制品文件
      - 应用 `context` 和 `rules` 作为约束（不要写入文件）
   b. 重复直到所有 `applyRequires` 制品完成

5. **展示最终状态**
   ```bash
   openspec status --change "<name>"
   ```

**输出示例**

```
## 新需求已创建: 2026-05-01-add-comment-api

### 制品清单
- proposal.md — 为什么做：将评论功能从 GitHub API 迁移到自有后端
- design.md — 技术方案：NestJS Comment 模块 + MongoDB 存储
- tasks.md — 6 个实施步骤
- specs/comment-api/spec.md — 增量需求规格

所有制品已生成，可以开始实现。执行 `/开始执行` 开始写代码。
```

**注意事项**
- 使用 YYYY-MM-DD-{task-name} 命名格式
- 所有输出文档使用中文
- 关键字（tasks, proposal, design, specs, ADDED, MODIFIED, REMOVED）保留英文
- 如果同名变更已存在，询问用户是继续还是新建
