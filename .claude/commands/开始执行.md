执行 OpenSpec 变更中的任务清单，按 tasks.md 逐步实现。

**输入**: 可选指定变更名称（如 `/开始执行 2026-05-01-add-auth`）。如果省略，从对话上下文推断或列出可选变更。

**步骤**

1. **选择变更**
   如果提供了名称，直接用。否则:
   - 从对话上下文推断
   - 只有一个活跃变更时自动选择
   - 多变更时运行 `openspec list --json`，用 **AskUserQuestion** 让用户选择
   始终先提示: "将执行变更: <name>" 以及如何覆盖

2. **检查状态**
   ```bash
   openspec status --change "<name>" --json
   ```
   - 如果 `state: "blocked"`（缺少制品）: 提示先用 `/新需求` 补齐
   - 如果 `state: "all_done"`: 提示所有任务已完成，建议 `/归档`
   - 否则: 继续执行

3. **获取执行指令**
   ```bash
   openspec instructions apply --change "<name>" --json
   ```
   读取返回的 `contextFiles` 中所有文件

4. **展示当前进度**
   ```
   ## 开始执行: <变更名称>

   进度: 2/6 任务完成
   剩余任务:
   - [ ] 创建 repos 模块
   - [ ] 注册到 app.module
   - [ ] 更新 shared-contracts
   - [ ] 前端 API 层
   ```

5. **逐任务实现（循环直到完成或卡住）**
   每个任务:
   - 提示正在做哪个任务
   - 做代码改动（最小化，聚焦）
   - 完成后标记 tasks.md: `- [ ]` → `- [x]`
   - 继续下一个

   暂停条件:
   - 任务不清晰 → 请用户说明
   - 实现过程中发现设计问题 → 建议更新设计制品
   - 遇到错误或阻塞 → 报告并等待指示
   - 用户中断

6. **完成后展示状态**

**输出示例（实现中）**

```
## 执行中: 2026-05-01-standardize-api (schema: spec-driven)

正在做任务 3/6: 标准化分页响应格式
[...代码改动...]
✓ 任务完成

正在做任务 4/6: 添加 404 异常处理
[...代码改动...]
✓ 任务完成
```

**输出示例（完成）**

```
## 执行完成

**变更:** 2026-05-01-standardize-api
**进度:** 6/6 任务全部完成 ✓

### 本次完成
- [x] 创建 common 基础设施
- [x] 修复 Query DTO
- [x] 标准化分页响应
- [x] 添加 404 处理
- [x] 注册全局异常过滤器
- [x] 接入 Swagger

所有任务完成！可以执行 `/归档` 归档此变更。
```

**注意事项**
- 逐个任务持续推进，直到完成或被阻塞
- 每次开始前读取所有上下文文件
- 任务不明确时暂停、询问，不要猜测
- 实现过程中发现设计问题及时提出
- 代码改动保持最小化和聚焦
- 每完成一个任务立即标记 checkbox
- 所有输出使用中文
