- **计划文档 / Plan Doc**：`codex/plan/frontend_task_prompt-message-2026-03-22.md`
- **任务分级与预算 / Sizing & Budget**：`M` 级任务；预计 1-2 天；子任务数 3；首轮读取不超过 15 个文件或 1500 行；超预算条件：需要改动全局主题/路由/引入新依赖。
- **任务背景 / Background**：当前系统提示使用 `window.alert`，体验与样式不一致。需要实现 Ant-design 风格 Message 组件，支持多状态、可关闭、可配置位置。当前分支：`45-feat-新增message提示组件`，需遵守 `CODEX_RULES.md` 输出顺序与“无新依赖”。
- **目标与范围 / Goals**
  - 必须完成：
  - 提供 Message 组件（Ant-design 风格）
  - 支持多种状态（如 success/info/warning/error/loading）
  - 支持手动关闭（close icon）
  - 支持指定提示位置（如 top/top-right/bottom 等）
  - 支持自动消失（可配置 duration）
  - 可选增强：
  - 支持 maxCount 与队列
  - 支持全局 API（如 `message.success('text')`）
  - 支持自定义 icon/内容
  - 不在范围：
  - 与后端交互、服务端推送
  - Toast 历史持久化
- **交互与设计 / UX**：参考 Ant Design Message：轻量浮层、圆角、轻阴影、进入/退出动效；支持关闭按钮；不同状态有颜色/图标差异；暗色模式适配。
- **技术栈约束 / Tech Stack**：Next.js + React + styled-components；禁止新增依赖；组件位于 `packages/components` 并导出；仅在任务范围内修改。
- **数据与接口 / Data**：纯前端，无 API。
- **状态与权限 / State & Auth**：全局展示状态由 Message 管理器维护；无权限要求。
- **可观测性 / Observability**：暂无埋点需求（TBD）。
- **开发步骤建议 / Execution Order**：
  1. 设计组件 API 与全局调用方式（静态方法 / hook / context）。
  2. 实现消息容器与队列管理（位置、stacking、duration、close）。
  3. 补齐样式与动效，完成暗色模式适配。
  4. 更新 README/示例与导出入口。
- **交付物 / Deliverables**：
  - `packages/components/message/*`
  - 组件导出入口（如 `packages/components/index.ts`）
  - README/用法示例
- **校验标准 / Validation**：
  - 正常：多状态显示正确；支持关闭；支持位置配置；自动消失。
  - 异常：短时间多次触发不崩溃；超过 maxCount 的处理符合预期（若实现）。
  - 边界：duration=0 保持常驻；快速连续关闭不报错。
- **验证策略 / Verification Strategy**：

  - 最终全量验证命令：`pnpm lint && pnpm typecheck`（TBD）
  - CI 验证要求：无（TBD）

- **Assumptions**：
  - 假设：Message 为全局浮层，不依赖页面布局
  - 假设：不新增第三方依赖
  - 假设：样式与主题变量一致并支持暗色模式
  - 假设：位置枚举采用 `top`/`topLeft`/`topRight`/`bottom`/`bottomLeft`/`bottomRight`，默认 `top`
  - 假设：默认 `duration=3` 秒，支持 `duration=0` 常驻；`loading` 默认 `duration=0`
  - 假设：提供 antd 风格 API（`message.open` + `message.success/info/warning/error/loading` + `message.config`）
  - 假设：默认 `maxCount=5`，超出时移除同 placement 最早一条
  - 假设：关闭方式为自动 + 手动（close icon），不支持点击外部关闭
  - 假设：进入/退出动效为轻微 fade + slide
