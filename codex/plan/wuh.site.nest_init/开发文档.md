2. 数据模型（MongoDB）
2.1 Content Schema
Ts
@Schema({ timestamps: true })
export class Content {
  @Prop({ required: true, unique: true }) externalId: number; // GitHub issue id
  @Prop({ required: true }) repo: string;
  @Prop({ required: true }) number: number;
  @Prop({ required: true }) title: string;
  @Prop({ type: [String], default: [] }) labels: string[];
  @Prop({ required: true }) state: 'open' | 'closed';
  @Prop() body: string;
  @Prop() bodyHtml?: string;
  @Prop({
    type: Object,
    default: {},
  })
  metadata: {
    slug?: string;
    summary?: string;
    cover?: string;
    keywords?: string[];
    rssExcluded?: boolean;
    extra?: Record<string, unknown>;
  };
  @Prop() author: { login: string; avatarUrl: string; url: string };
  @Prop({ default: 0 }) comments: number;
  @Prop() createdAtGitHub: Date;
  @Prop() updatedAtGitHub: Date;
  @Prop() publishedAt?: Date;
}
2.2 Comment Schema
Ts
@Schema({ timestamps: true })
export class Comment {
  @Prop({ required: true, unique: true }) externalId: number; // GitHub comment id
  @Prop({ required: true }) issueId: number; // issue id
  @Prop({ required: true }) issueNumber: number;
  @Prop({ required: true }) repo: string;
  @Prop({ required: true }) body: string;
  @Prop({ required: true }) bodyHtml?: string;
  @Prop({ required: true })
  user: {
    login: string;
    avatarUrl: string;
    url: string;
  };
  @Prop() nickname?: string;
  @Prop() email?: string;
  @Prop() avatarUrl?: string; // 随机头像

  @Prop() updatedAtGitHub: Date;

bodyHtml 可选；匿名评论的 nickname/avatar 覆盖在响应中返回。

3. 服务与流程
3.1 SyncService
提供 fullSync()、syncIssue(issueNumber)、syncComment(commentId) 等方法。
fullSync:
使用 GitHub REST API 分页获取 Issues（按 label 或 repo 全量）。
对每个 Issue 获取 comments。
Upsert 到 Mongo。
Webhook 调用 syncIssue / syncComment 实现增量更新。
考虑 GitHub Rate Limit，必要时缓存 ETag。
3.2 WebhookModule
路由 POST /webhook/github
验证 X-Hub-Signature-256。
事件：
issues: 触发 syncIssue(number)
issue_comment: 触发 syncComment(comment_id) + syncIssue（更新统计）
失败时写日志 + Sentry。
3.3 CommentModule
POST /comments
DTO: CreateAnonymousCommentDto { nickname: string; email?: string; content: string }
逻辑：
Rate limit Guard。
生成 avatarUrl：可用 gravatar identicon (md5(email || nickname))，或随机 UI Avatars。
构造 GitHub comment body，并调用 GitHub API。
写入 Mongo，记录 footPrint(uuid) + clientIp + userAgent。
GET /comments
查询 Mongo comment 集合（分页）。
返回 GitHub 风格字段 + nickname/avatar。
3.4 ContentModule
GET /content/posts 等：查询 Content 集合，按 label/metadata 过滤。
GET /content/posts/:slug：根据 metadata.slug 或 number、externalId 查询。
3.5 RSSModule
RssService.generateFeed()：从 Mongo 查数据，使用 feed 包生成 XML。
GET /rss.xml：使用缓存（Memory/Redis）。当 Webhook 更新内容后，调用 RssService.clearCache()。
3.6 AdminModule（可后续实现）
提供 PATCH /content/:id/metadata 等接口，仅 writer/root 使用。

.env: SENTRY_DSN=...

6. 初次同步脚本
路径：scripts/sync-init.ts
伪代码：
Ts
async function bootstrap() {
  const app = await NestFactory.createApplicationContext(AppModule, {
    logger: ['log', 'error', 'warn'],
  });
  const syncService = app.get(SyncService);
  await syncService.fullSync();
  await app.close();
}
bootstrap().catch((err) => {
  console.error(err);
  process.exit(1);
});
package.json: "sync:init": "ts-node -P tsconfig.json scripts/sync-init.ts"

8. 安全与合规
Webhook 签名校验必须启用。
匿名留言：需对 email/nickname 做基本过滤，防止 XSS。
速率限制：@nestjs/throttler（如 limit=5, ttl=60）应用于匿名留言接口。
环境变量中 token/secret 不应在日志中输出。
生产部署中 Sentry DSN、Mongo URI 等敏感信息需通过安全管道注入。
