需求文档（Product Requirements Document, PRD）
1. 背景与目标
现有博客内容存放于独立仓库 stack-wuh/blog，所有文章与留言依赖 GitHub Issues。
新后端 wuh.site.nest 需要：
对博客内容进行可控的本地缓存（MongoDB），方便前端和其他服务统一调用。
支持匿名留言，自动同步到指定的 GitHub Issue，并存储到 Mongo。
提供 RSS 订阅、日志监控、手动初次同步等能力。
前端 wuh.site.next 仍沿用 GitHub 的数据结构，因此后端需要提供兼容数据。
2. 功能需求
2.1 内容同步与缓存
全量数据从 GitHub Issue 拉取，存入 Mongo。
日常通过 GitHub Webhook（issues + issue_comment）触发增量更新。
后端 API 仅访问 Mongo，不直接调用 GitHub。
2.2 内容 API
GET /content/posts、GET /content/projects 等接口，返回数据结构需兼容 GitHub 的 Issue fields，额外提供 metadata。
支持 slug 或 number 查询单篇内容。
metadata 字段用于扩展：slug, summary, cover, keywords, rssExcluded, extra。
2.3 匿名留言系统
前端提交 nickname、email（可选）、content。
服务端使用预置 GitHub Token，将留言写入指定 Issue。
评论以 GitHub 风格存储到 Mongo，同时记录 nickname、email、随机头像、footprint 等。
GET /comments 返回 Mongo 数据，保留 GitHub comment 字段格式。
2.4 RSS 订阅
提供单一路由 GET /rss.xml，包含所有可订阅内容（metadata.rssExcluded !== true）。
RSS 内容来自 Mongo，使用 metadata 字段填充 <link>、<description>、<enclosure> 等。
支持缓存（内存/Redis），确保 Webhook 更新后可清理缓存。
2.5 初次同步
提供脚本 npm run sync:init，执行全量同步，部署或迁移时手动运行一次。
2.6 监控与日志
使用 Pino 输出结构化日志。
生产环境集成 Sentry 捕获异常，并对关键流程（Webhook、同步、GitHub API）进行监控。
2.7 角色管理（基础）
角色定义：root、writer、reader。
目前关注点在留言/内容查询，不涉及复杂权限控制；后续 Admin 接口可依据角色扩展。
3. 非功能需求
所有对 GitHub 的请求均在服务端执行，前端只访问后端 API。
API 需 SSR-safe，可供 wuh.site.next 使用。
匿名留言需具备防 spam 策略（Rate limit 必备，Captcha 可以后续补充）。
Webhook 接口需进行 GitHub 签名校验。
所有配置通过环境变量下发，并保证敏感数据（tokens、Sentry DSN）不暴露。
